
 04. 데이터

## 1. 개요

EC2에 직접 설치해 운영하던 DB를 AWS RDS MySQL로 전환해 백업, 패치, 장애 복구 부담을 줄였습니다. 데이터는 성격에 따라 나눠 저장합니다.

| 데이터 | 저장소 |
| --- | --- |
| 서비스 데이터 | RDS MySQL |
| 유사도 분석용 벡터 파일 | S3 (FastAPI 시작 시 다운로드해 로딩) |

## 2. RDS 구성

| 항목 | 값 |
| --- | --- |
| 엔진 / 인스턴스 | MySQL 8.4 / db.t3.micro (2 vCPU, 1GB) |
| 스토리지 | gp3 20GiB, 자동 조정(최대 1000GiB), 암호화 적용 |
| 배치 | DB Private Subnet (인터넷 경로 없음) |
| 접근 제어 | Spring Boot 보안 그룹의 TCP 3306만 허용 |

- 서비스 규모와 비용을 고려해 최소 사양으로 시작하고, 부하가 늘면 인스턴스 클래스를 상향합니다.
- 외부에서 DB로 직접 접속할 수 없고, 애플리케이션 서버를 통해서만 접근합니다.

## 3. 벡터 파일 (S3)

- 유사도 분석에 쓰는 벡터 파일을 S3에 저장합니다.
- FastAPI 인스턴스가 시작할 때 내려받아 메모리에 로딩하고, 로딩이 끝나야 `/health`가 200을 반환합니다.
- IAM 인스턴스 프로파일로 읽기 권한만 부여하고, 버킷은 퍼블릭 액세스를 차단합니다.

## 4. RDS 가용성과 복구

- Multi-AZ 구성으로 서로 다른 가용 영역에 DB 분산 배치
- Primary 장애 발생 시 Standby 인스턴스로 자동 Failover
- RDS 엔드포인트를 유지하여 애플리케이션 연결 변경 최소화
- 자동 백업 및 스냅샷을 통한 데이터 복구 지원
- 측정 결과는 [06.failure-test](06.failure-test.md)에 기록합니다.
