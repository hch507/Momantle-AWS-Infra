# 01. Network Architecture

## 1. Region 및 Availability Zone

- **Region:** ap-northeast-2 (서울)
- **Availability Zone:**
  - ap-northeast-2a
  - ap-northeast-2b

2개의 Availability Zone을 활용하여 Auto Scaling Group의 인스턴스 배치 범위를 구성하였다.

특정 EC2 인스턴스에 장애가 발생하면 Auto Scaling Group의 헬스체크를 통해 비정상 인스턴스를 감지하고, 설정된 용량 및 배치 정책에 따라 새로운 인스턴스를 생성하여 서비스 가용성을 유지하도록 설계하였다.

## 2. VPC 구성

- **VPC Name:** momantle-ap2-vpc
- **IPv4 CIDR:** 10.0.0.0/16

서비스 운영에 필요한 네트워크 자원을 하나의 VPC 내에서 관리하며, Public 및 Private Subnet을 분리하여 외부 접근 범위를 제한하였다.

## 3. Subnet 구성

### 3.1 AZ: ap-northeast-2a

| 구분 | Subnet Name | CIDR |
|---|---|---|
| Public | subnet-public1 | 10.0.0.0/20 |
| App Private | subnet-private3 | 10.0.160.0/20 |
| DB Private | subnet-private1 | 10.0.128.0/20 |

### 3.2 AZ: ap-northeast-2b

| 구분 | Subnet Name | CIDR |
|---|---|---|
| Public | subnet-public2 | 10.0.16.0/20 |
| App Private | subnet-private2 | 10.0.144.0/20 |
| DB Private | subnet-private4 | 10.0.176.0/20 |

### 3.3 Subnet별 역할

- **Public Subnet:** Internet Gateway를 통한 외부 통신 및 NAT Instance 배치
- **App Private Subnet:** 애플리케이션 서버 배치 및 NAT Instance를 통한 외부 통신
- **DB Private Subnet:** RDS 배치 및 인터넷으로의 직접적인 외부 통신 차단

## 4. Internet Gateway 구성

- **Gateway:** Internet Gateway
- **연결 대상:** momantle-ap2-vpc
- **사용 목적:** Public Subnet의 인터넷 통신 지원

Internet Gateway를 VPC에 연결하고 Public Subnet의 Route Table에 기본 경로를 설정하여 외부 인터넷과의 통신이 가능하도록 구성하였다.

Private Subnet은 Internet Gateway를 통한 직접적인 외부 통신을 허용하지 않는다.

## 5. Routing 구성

각 Subnet의 역할과 네트워크 접근 목적에 따라 Route Table을 분리하여 트래픽 흐름을 제어하였다.

### 5.1 Route Table별 주요 경로

| 구분 | Destination | Target |
|---|---|---|
| Public RT | 10.0.0.0/16 | local |
| Public RT | 0.0.0.0/0 | Internet Gateway |
| App RT (2a) | 10.0.0.0/16 | local |
| App RT (2a) | 0.0.0.0/0 | NAT Instance (2a) |
| App RT (2b) | 10.0.0.0/16 | local |
| App RT (2b) | 0.0.0.0/0 | NAT Instance (2b) |
| DB RT (2a) | 10.0.0.0/16 | local |
| DB RT (2b) | 10.0.0.0/16 | local |

### 5.2 Subnet별 외부 통신 경로

| 구분 | 외부 통신 경로 |
|---|---|
| Public Subnet | Internet Gateway |
| App Private Subnet (2a) | NAT Instance (2a) |
| App Private Subnet (2b) | NAT Instance (2b) |
| DB Private Subnet (2a) | 외부 인터넷 경로 없음 |
| DB Private Subnet (2b) | 외부 인터넷 경로 없음 |

모든 서브넷에는 VPC 내부 통신을 위한 Local Route가 존재한다.

**App Private Subnet**

각 AZ에 배치된 NAT Instance를 통해 외부 인터넷으로 나갈 수 있도록 구성하였다. AZ별 NAT Instance를 사용하여 외부 통신 경로를 독립적으로 구성하고 AZ 간 NAT 트래픽을 최소화하였다.

**DB Private Subnet**

DB Private Subnet은 데이터베이스 운영을 위한 독립적인 네트워크 영역으로 구성하였다.

- VPC 내부 통신을 위한 Local Route 유지
- Internet Gateway 및 NAT Instance를 통한 외부 인터넷 경로 미구성
- 애플리케이션 서버에서 필요한 포트(3306)로만 접근하도록 Security Group 설정

데이터베이스가 외부 인터넷과 직접 통신할 필요가 없으므로 불필요한 외부 네트워크 접근을 차단하였다.

## 6. NAT Instance 구성

- **NAT 방식:** NAT Instance
- **배치 위치:** 각 AZ의 Public Subnet
- **라우팅:** 각 AZ의 App Private Subnet과 연결
- **주요 역할:** Private Subnet에서 시작한 외부 통신을 NAT 처리

NAT Gateway 대비 비용을 절감하기 위해 NAT Instance를 선택하였다.

AZ별 NAT Instance를 배치하여 AZ 간 NAT 트래픽을 최소화하고, AZ별 외부 통신 경로를 독립적으로 구성하였다.

NAT Instance 장애 발생 시 해당 AZ의 App Private Subnet에서 외부 통신이 중단될 수 있으므로 장애 대응 방안을 고려해야 한다.

## 7. 네트워크 설계 목적

- Public / Private Subnet 분리를 통한 네트워크 격리
- 애플리케이션 서버와 데이터베이스의 접근 영역 분리
- AZ 분산을 통한 가용성 확보 기반 마련
- NAT Instance를 활용한 Private Subnet의 외부 통신 지원
- 불필요한 외부 네트워크 접근 차단
- Route Table을 활용한 네트워크 트래픽 경로 제어
