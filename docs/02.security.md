# 02. Security Architecture

## 1. Security Group 기반 계층별 접근 제어

서비스 계층별로 Security Group을 분리하여 필요한 리소스 간 통신만 허용하도록 구성하였다.

### 1.1 외부 ALB (alb-ext-sg)

- **Inbound:** TCP 80 / 0.0.0.0/0
- **Outbound:** 전체 허용
- **역할:** 외부 사용자 요청 수신 및 Spring Boot 서버로 전달

### 1.2 Spring Boot (momantle-dev-spring-sg)

- **Inbound:** TCP 8080 / alb-ext-sg
- **Outbound:** 전체 허용
- **역할:** 외부 ALB를 통한 API 요청 처리, Internal ALB를 통한 FastAPI 호출 및 RDS 접근

### 1.3 내부 ALB (alb-int-sg)

- **Inbound:** TCP 80 / momantle-dev-spring-sg
- **Outbound:** 전체 허용
- **역할:** Spring Boot 서버에서 전달되는 내부 요청 수신 및 FastAPI로 전달

### 1.4 FastAPI (momantle-dev-fastapi-sg)

- **Inbound:** TCP 8000 / alb-int-sg
- **Outbound:** 전체 허용
- **역할:** 내부 ALB를 통한 AI 유사도 분석 요청 처리

### 1.5 RDS MySQL (momantle-rds-sg)

- **Inbound:** TCP 3306 / momantle-dev-spring-sg
- **Outbound:** 전체 허용
- **역할:** Spring Boot 서버에서 발생하는 데이터베이스 접근 허용

### 1.6 NAT Instance (momantle-nat-sg)

- **Inbound:** 전체 트래픽 / momantle-dev-spring-sg
- **Inbound:** 전체 트래픽 / momantle-dev-fastapi-sg
- **Outbound:** 전체 허용
- **역할:** Private Subnet에 위치한 애플리케이션 서버의 외부 인터넷 통신 중계

## 2. 서버 접근 제어

### 2.1 SSH 접근 제한

- 외부 인터넷에서 EC2로 직접 접근하는 SSH(22) 포트 미개방
- SSH Key를 통한 직접 접속 대신 AWS Systems Manager 활용

### 2.2 AWS Systems Manager (SSM)

- EC2에 IAM Role 연결
- AmazonSSMManagedInstanceCore 정책 적용
- Session Manager를 통한 원격 접속
- 인바운드 SSH 포트 개방 없이 서버 관리

SSM을 활용하여 외부에 SSH 포트를 노출하지 않고 EC2 인스턴스에 안전하게 접근할 수 있도록 구성하였다.

## 3. IAM 접근 권한 관리

- IAM Role을 통한 EC2의 AWS 서비스 접근 권한 관리
- 필요한 리소스에 최소 권한 부여
- 불필요한 관리자 권한 사용 제한

## 4. 보안 설계 방향

- Security Group을 활용한 서비스 계층별 접근 제어
- 데이터베이스 외부 직접 접근 차단
- 내부 애플리케이션 서버의 외부 직접 접근 제한
- SSH 포트 미개방 및 SSM 기반 서버 관리
- Public / Private Subnet 분리를 통한 네트워크 접근 영역 분리
- 서비스 간 필요한 포트만 허용하는 네트워크 접근 정책 적용
