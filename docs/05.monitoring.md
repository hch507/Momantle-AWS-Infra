
# 7. 배포 및 모니터링

## 7.1 모니터링 아키텍처

AWS CloudWatch를 활용하여 애플리케이션, 로드밸런서, 데이터베이스 및 Auto Scaling 상태를 통합 모니터링하도록 구성했습니다.

주요 모니터링 대상은 다음과 같습니다.

- **External ALB:** 외부 요청에 대한 HTTP 오류 및 응답 시간 모니터링
- **Internal ALB:** 내부 FastAPI 서비스의 HTTP 오류 모니터링
- **EC2:** Spring Boot 및 FastAPI 서버의 CPU 사용률 모니터링
- **RDS:** 데이터베이스 CPU 사용률, 연결 수, 여유 스토리지 모니터링
- **Auto Scaling:** 인스턴스 확장 및 축소를 위한 CloudWatch Alarm 관리

## 7.2 CloudWatch Dashboard

`LexiMatch-Monitoring` 대시보드를 생성하여 인프라 주요 지표를 한곳에서 확인할 수 있도록 구성했습니다.

### ① Load Balancer 모니터링

External ALB와 Internal ALB의 요청 처리 상태를 모니터링합니다.

| 지표 | 모니터링 목적 |
|---|---|
| HTTPCode_ELB_5XX_Count | ALB에서 발생한 서버 오류 확인 |
| HTTPCode_Target_5XX_Count | 대상 EC2에서 발생한 서버 오류 확인 |
| TargetResponseTime | 대상 서버의 응답 시간 확인 |

### ② Application 서버 모니터링

Spring Boot와 FastAPI EC2의 CPU 사용률을 모니터링합니다.

| 지표 | 모니터링 목적 |
|---|---|
| CPUUtilization | EC2 CPU 사용률 확인 |

Auto Scaling 환경에서는 인스턴스 교체가 발생하므로 개별 Instance ID가 아닌 AutoScalingGroupName 차원을 활용하는 방식으로 개선하여 그룹 단위의 모니터링을 구성합니다.

### ③ RDS 모니터링

데이터베이스의 리소스 사용량과 연결 상태를 확인합니다.

| 지표 | 모니터링 목적 |
|---|---|
| CPUUtilization | 데이터베이스 CPU 사용률 |
| DatabaseConnections | 현재 DB 연결 수 |
| FreeStorageSpace | 남은 스토리지 용량 |

이를 통해 데이터베이스의 부하 증가 및 스토리지 부족 가능성을 확인할 수 있도록 구성했습니다.

## 7.3 CloudWatch Alarm

CloudWatch Alarm을 활용하여 인프라 이상 상태 및 Auto Scaling 조건을 감지하도록 구성했습니다.

### ① Auto Scaling Target Tracking

Spring Boot와 FastAPI Auto Scaling Group에 Target Tracking 정책을 적용했습니다.

- CPU 사용률을 기준으로 인스턴스 수를 자동 조정
- 목표 CPU 사용률을 기준으로 Scale Out 및 Scale In 수행
- CloudWatch Alarm을 통해 확장 및 축소 조건 감지

Target Tracking 정책 생성 시 AWS가 다음과 같은 CloudWatch Alarm을 자동 생성합니다.

| Alarm | 역할 |
|---|---|
| TargetTracking-asg-fastapi-AlarmHigh | CPU 사용률이 목표보다 높을 때 Scale Out 판단 |
| TargetTracking-asg-fastapi-AlarmLow | CPU 사용률이 목표보다 낮을 때 Scale In 판단 |
| TargetTracking-asg-spring-AlarmHigh | Spring Boot 서버 Scale Out 판단 |
| TargetTracking-asg-spring-AlarmLow | Spring Boot 서버 Scale In 판단 |

### ② 서비스 상태 모니터링

서비스 및 로드밸런서의 이상 상태를 감지하기 위한 별도 Alarm을 구성했습니다.

| Alarm | 감지 대상 |
|---|---|
| alarm-spring-unhealthy | Spring Boot 대상의 비정상 상태 |
| alarm-fastapi-unhealthy | FastAPI 대상의 비정상 상태 |
| alarm-service-down | 서비스 상태 이상 |

각 Alarm의 상태를 CloudWatch에서 확인하여 서비스 장애 여부를 파악할 수 있도록 구성했습니다.

## 7.4 모니터링 운영 및 개선 방향

Auto Scaling 환경에서는 EC2 인스턴스가 종료되고 새로운 인스턴스로 교체될 수 있습니다.

개별 EC2 Instance ID를 기준으로 모니터링하면 인스턴스 교체 이후 새로운 인스턴스의 지표가 기존 대시보드에 반영되지 않을 수 있습니다.

이를 개선하기 위해 다음과 같은 모니터링 기준을 적용합니다.

- EC2 CPU 지표: AutoScalingGroupName 차원 활용
- Auto Scaling 상태: GroupDesiredCapacity, GroupInServiceInstances 등 활용
- ALB 상태: HealthyHostCount, UnHealthyHostCount 활용
- RDS 상태: CPU, 연결 수, 스토리지 지표 지속 확인

이를 통해 인스턴스 교체 및 자동 확장 상황에서도 인프라 전체의 운영 상태를 확인할 수 있도록 개선합니다.
